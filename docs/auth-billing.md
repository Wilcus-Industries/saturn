# Auth, billing, tiers

> Part of the Saturn docs set indexed in `CLAUDE.md`. Update both in the same change.

## Auth + billing (the core of the app)

Everything flows through better-auth, configured in `lib/auth.ts`:

- Google OAuth = only sign-in method (unless `SELF_HOSTED=1` — then no sign-in at all; see "Self-hosted mode").
- `app/api/auth/[...all]/route.ts` = single catch-all for all auth routes **and** Stripe webhook (`/api/auth/stripe/webhook`) — stripe plugin handles webhooks (plugin absent under `SELF_HOSTED=1`); don't add separate webhook route. Other routes under `app/api/` = MCP OAuth callback (`app/api/mcp/oauth/callback/route.ts`) + the three central GitHub App routes (`app/api/github/webhook/route.ts` HMAC-verified event ingress, `app/api/github/install/route.ts` + `app/api/github/callback/route.ts` install/OAuth-link flow — see "Extension event nodes") + the per-workflow inbound webhook ingress (`app/api/hooks/[workflowId]/[secret]/route.ts` — no env gate, POST only, 202 fire-and-forget; see "Extension event nodes"). Outside `app/api/`: hosted MCP server at `app/mcp/route.ts` + root OAuth discovery documents (`app/.well-known/oauth-authorization-server/` + `oauth-protected-resource/` and its `/mcp`-suffixed form) — see "Hosted MCP server" below.
- `mcp` plugin (better-auth built-in) makes catch-all an OAuth 2.1 authorization server (dynamic client registration + PKCE at `/api/auth/mcp/authorize|token|register`) for hosted MCP server; `loginPage: "/onboard"` — unauthenticated authorize request bounces through Google sign-in, resumes automatically. **Consent forced** (fixes cross-account-takeover: plugin issues code with no consent unless request carries `prompt=consent` — with anonymous client registration + Lax session cookie, logged-in victim could be lured to authorize URL that silently minted token for attacker's client). Root-level **`proxy.ts`** (Next 16 renamed middleware; matcher `/api/auth/mcp/authorize`) redirects every authorize request to itself with `prompt=consent` added; `mcp({ oidcConfig: { consentPage: "/oauth/consent" } })` routes it to first-party consent screen `app/oauth/consent/page.tsx` (server component; Approve/Deny posts through server action to `auth.api.oAuthConsent`, then redirects to client callback). Do not remove proxy or `consentPage` without replacing consent gate. Post-login resume covered — plugin replays already-amended query from signed cookie. Its tables (`oauthApplication`, `oauthAccessToken`, `oauthConsent`) better-auth-owned — migrate via CLI, never `db/setup.sql`.
- `nextCookies` plugin must stay last in plugins array.
- `session.cookieCache` enabled (60s maxAge): session data rides signed cookie, skips per-request session SELECT. `user.plan` in cached payload → plan changes/remote sign-outs stale ≤60s — don't raise maxAge without revisiting activate/upgrade flows (`refreshCache` must stay unset; DB-backed setups warn). `getSessionCached` in `lib/subscription.ts` (React `cache()`) also dedupes session resolution per request — pages/actions use it, never `auth.api.getSession` directly.
- `databaseHooks.user.create.after` seeds every new user inactive "Daily haiku" example workflow (`seedExampleWorkflow` in `lib/exampleWorkflow.server.ts` — inserted `active=false`; seed failures logged + swallowed, never break signup; counts against tier workflow cap, user-deletable like any workflow).
- better-auth owns its DB schema (tables like `user`, `session`, `subscription`) via shared `pg` Pool in `lib/db.ts`. App-owned tables live in `db/setup.sql` — never redefine better-auth tables there.

Three activation tiers, two billing mechanisms:

- `pro` ($19/mo) and `max` ($79/mo) = Stripe subscriptions managed by `@better-auth/stripe` plugin (price IDs from `STRIPE_PRICE_PRO`/`STRIPE_PRICE_MAX`).
- Tiers sell **platform limits and built-in model credits**: `PLAN_LIMITS` in `lib/subscription.ts` (workflows 3/20/100, MCP servers 3/10/50, `memoryStores` 1/5/20, `sandboxes` 1/3/5 plus per-tier sandbox resource quotas `sandboxMemoryMb` 128/256/512, `sandboxCpus` 0.25/0.5/1, `sandboxDiskMb` 512/2048/4096, `sandboxExecTimeoutS` 60/120/300, `cronFloorMinutes` 60/5/1 — tightest schedule tier may run, `modelCredits` 1,000/15,000/60,000 — per Stripe billing period on paid tiers, rolling 30-day window on free; see "Model access"). Count caps enforced server-side in `createWorkflow`, `saveMcpServer`, `saveMemoryStore`, `saveSandbox` (`limitsFor` treats not-activated user as `free`); sandbox **resource** quotas apply at container create/exec time in `lib/sandbox.server.ts`, not at save. Tier card copy (`TIERS` pricing/copy + `TIER_BUTTON` — must stay literal class strings for Tailwind) lives in `app/(saturn)/activate/tierCard.tsx`, shared with `/dashboard/upgrade`, must stay in sync with `PLAN_LIMITS`. Cron floor (schedules live in `schedule` event node, not workflow row) enforced two ways: designer cron picker caps offered intervals to `cronFloorMinutes` (`CronBuilder` `floorMinutes` prop, fed from designer page `limitsFor(level)`), and — authority — runner claim guard silently clamps downgraded/too-tight cron to floor at run time (`max(50, floor*60-30)` seconds). No save-time hard check (`assertCronFloor` removed); `validateGraphStrict` only warns on blank/invalid schedule cron.
- `free` = non-Stripe tier stored as `plan` column on `user` (better-auth `additionalFields` entry with `input: false` so clients can't set it; written by raw SQL in `app/(saturn)/activate/actions.ts` and `app/dashboard/(shell)/upgrade/actions.ts`).
- `lib/subscription.ts` = single source of tier logic — don't re-derive:
  - `getActivation(headers)` → effective level: active/trialing Stripe subscription wins (max > pro), then `free`, then `null` (not activated).
  - `getActivationDetails(headers)` adds `status`, `pendingCancel` (checks both `cancelAtPeriodEnd` and `cancelAt` — Stripe portal cancellation sets only latter), `periodEnd`.
  - `requireUser()` — session check + redirect to `/onboard`; used by every server action.
  - `getSessionCached()` — request-memoized session resolver (see cookieCache bullet).
  - `getActivationLevels(userIds)` — headless batch resolver for cron runner (same semantics as `getActivation`, one direct query against `"user"` + better-auth `subscription` table instead of request headers).
  - Also exports `LEVEL_RANK`, `isPaidPlan`, `baseUrl`, `PLAN_LIMITS`, `limitsFor`.

**Self-hosted mode** (`SELF_HOSTED=1`, server-only env in `lib/selfhost.ts` → `export const SELF_HOSTED`; server helpers in `lib/selfhost.server.ts`): single-owner instance, no user system. **No sign-in** — a synthetic owner (`SELF_HOSTED_USER_ID = "self-hosted-owner"`) is insert-once created on first boot (`ensureSelfHostedUser`, seeds the example workflow the create hook would have), and `getSessionCached` short-circuits to a synthetic session (`selfHostedSession`) instead of better-auth; dashboard is **unauthenticated**, so the operator must bind localhost or front it with reverse-proxy auth. Landing page removed under the flag — `/` redirects straight to `/dashboard` (with `/onboard`, `/activate`, `/dashboard/upgrade` — the marketing/plan surface is gone entirely). Effective level is **always `"max"`** (`getActivationDetails`/`getActivationLevels` short-circuit) and `limitsFor` returns `SELF_HOSTED_LIMITS` (all counts `Infinity`, `cronFloorMinutes` 1, `modelCredits` 0, sandbox quotas from env — below). **Two crash invariants** under the flag (the `subscription` table + stripe-plugin `auth.api` endpoints don't exist): no code may run `subscription` SQL (`getActivationDetails` short-circuits before `listActiveSubscriptions`, `getActivationLevels`/`getCreditUsage` before their `subscription` join) and no code may call stripe-plugin `auth.api` — the Stripe plugin is **not constructed** in `lib/auth.ts` (`STRIPE_*` + `GOOGLE_*` env unneeded; mcp plugin still present). Model calls funded **only** by server env `PLATFORM_OPENROUTER_KEY` (no per-user BYOK): `getCreditUsage` returns `{level:"max", allowance:0}` (zeroed, no SQL/cache) so key-selection uses the platform key directly, and `recordUsage` is a no-op (nothing metered). Hosted MCP server (`/mcp`) authenticated by static bearer env `SELF_HOSTED_MCP_TOKEN` (timing-safe check; **unset → 401** every request, never an open server), dispatching as the owner; OAuth discovery routes (`app/.well-known/oauth-*`) **404 under the flag**. Sandbox per-container quotas env-overridable (`SELF_HOSTED_SANDBOX` in `lib/selfhost.server.ts`): `SANDBOX_MEMORY_MB` (1024), `SANDBOX_CPUS` (2), `SANDBOX_DISK_MB` (8192), `SANDBOX_EXEC_TIMEOUT_S` (600). **Run the better-auth migrate WITH `SELF_HOSTED=1` set** (`SELF_HOSTED=1 npx @better-auth/cli@latest migrate --config lib/auth.ts`) so the stripe plugin's `subscription` table is skipped consistently. **Never `import` `lib/selfhost` from a `"use client"` file** — `SELF_HOSTED` is server-only (not `NEXT_PUBLIC`), would inline `undefined` client-side; server code threads it down as props. Flag unset = exactly today's behavior.

Client-side auth: `authClient` from `lib/auth-client.ts` (`better-auth/react`).

## User flow

`/` (landing) → `/onboard` (Google connect; server-redirects signed-in users past) → `/activate` (pick tier; server actions set `plan='free'` or redirect Stripe Checkout) → `/dashboard`.

Plan changes after activation at `/dashboard/upgrade` (`changePlan`, `continueSubscription`, `downgradeToFree` in `app/dashboard/(shell)/upgrade/actions.ts`).


## Model access

Two funding paths for agent-node LLM calls, both through OpenRouter, selected per turn in `executeAgentTurn` (`lib/runner.server.ts` — single chokepoint for designer's `callAgentModel` action, cron runs, MCP server's `run_workflow`):

- **Built-in model credits** (every activated tier, incl. free): while tier allowance holds, calls run on platform key `PLATFORM_OPENROUTER_KEY` (optional env — unset degrades everyone to BYOK). Metering in `lib/credits.server.ts` (server-only): `model_usage` ledger in `db/setup.sql` = source of truth (no balance column, no reset job); `getCreditUsage(userId)` resolves tier + Stripe billing period headlessly (mirrors `getActivationLevels`; paid sub with null `periodStart` falls back to 30-day lookback, never unlimited), sums `credits` since `periodStart`, behind 60s in-process TTL cache that `recordUsage` increments in place on success (same-process balance checks stay exact; external writes stale ≤60s), drops on insert failure; `recordUsage` debits `ceil(usage.cost * 1000)` credits per platform-billed turn (1,000 credits = $1; raw cost kept as `cost_microdollars`), never throws — failed insert must not fail completed call. `chatComplete` (`lib/agent.server.ts`) requests `usage: {include: true}`, returns server-only `usage` field (never folded into client-crossing `AgentModelResult`). Allowances = `PLAN_LIMITS.modelCredits`. Free tier has no subscription period — window = same 30-day lookback, rolling month, not fixed reset. Not-activated users (level `null`) get **no** allowance: `getCreditUsage` zeroes it instead of using `limitsFor` null→free mapping (sybil guard — credits require at least picking free plan on `/activate`). Check-then-call-then-record deliberately non-transactional — concurrent turns can overshoot by ~one 8192-max_tokens turn each; accepted. Used/allowance bar = shared `CreditsBar` (`app/dashboard/creditsBar.tsx`), rendered whenever allowance > 0 ("resets {date}" paid, "past 30 days" free) on settings (Overview usage panel unmounted with the Agent page rework).
- **BYO OpenRouter key** (not-activated users / allowance exhausted): permanent fallback. Entered in "Models" section of `/dashboard/settings`, stored in app-owned `user_secret` table (`db/setup.sql`, one row per user, `openrouter_key` column), write-only per settings convention. `saveOpenrouterKey` in `app/dashboard/(shell)/settings/actions.ts`; server-side reads via `getOpenrouterKey`/`hasOpenrouterKey` in `lib/openrouter.server.ts`. Neither key ever leaves server; BYOK turns never recorded in ledger. No key + no credits → turn errors as value (upgrade/add-key hint).

When user has key set **or** is on activated tier with credit allowance (`limitsFor(level).modelCredits > 0` — any activated tier today, never level `null`), designer toolbox lists OpenRouter models (`listOpenrouterModels` in `lib/openrouter.server.ts` — public `GET https://openrouter.ai/api/v1/models`, deliberately unauthenticated so 1h-revalidate Next data cache shareable) as drag-spawnable model nodes. Each `OpenrouterModel` carries `outputModalities` (`architecture.output_modalities` filtered to `text`/`image`), driving agent node's dynamic `output` select, and `supportsReasoning` (`supported_parameters` includes `"reasoning"`), driving agent node's dynamic `reasoning` select.
