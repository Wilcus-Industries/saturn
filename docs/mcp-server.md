# Hosted MCP server (`/mcp`)

> Part of the Saturn docs set indexed in `CLAUDE.md`. Update both in the same change.

External agents (e.g. Claude Code: `claude mcp add --transport http saturn <baseUrl>/mcp`; shared "Connect an agent" card lists commands for Claude Code, Codex, Gemini CLI, VS Code, Cursor) edit + test-run authenticated user's workflows, and manage the registry they draw on (memory stores, skills, variables):

- `app/mcp/route.ts` — stateless Streamable-HTTP JSON-RPC handler (`export const dynamic = "force-dynamic"`): hand-rolled like client in `lib/mcp.ts`, plain JSON responses (no SSE, no session id, no batching), methods `initialize` (version negotiation 2024-11-05…2025-06-18) / `ping` / `tools/list` / `tools/call`; notifications → 202; `GET`/`DELETE` → 405. `POST` wrapped in `withMcpAuth(auth, …)` — bearer token resolves to `OAuthAccessToken` whose `userId` = only identity input; missing/invalid token 401s with `WWW-Authenticate` resource-metadata pointer.
- OAuth discovery: root `.well-known` routes (see Auth section) serve AS + protected-resource metadata; actual authorize/token/register endpoints live under better-auth catch-all.
- `app/mcp/protocol.ts` — JSON-RPC envelopes/negotiation; `app/mcp/tools.ts` — 27 tool definitions (hand-written JSON Schemas), graph-authoring guide `GRAPH_DOCS`, `dispatchTool(userId, name, args)`. **Workflows (12)**: `list_workflows`, `get_workflow` (annotates every graph node with read-only `label` resolved via per-user byKey catalog — uuid node types opaque, agents mislabel grants without it; labels re-resolved each read, harmless if echoed into `save_graph`), `create_workflow` (workflow cap via `getActivationLevels`)/`update_workflow` (metadata only — no cron param, schedule authored in graph via `save_graph`; update also takes boolean `active`), `delete_workflow`, `get_catalog` (static catalog + `buildUserCatalog`, minus `legacy`/`missing` entries — user registry entries sorted **first**, per-tool descriptions trimmed to first line ≤150 chars via `trimDescription`, both so agent-node caller's truncated view — interpreter's `MAX_MODEL_RESULT_CHARS` — never cuts user's own servers; full descriptions still reach model at runtime via `buildToolDefs`), `get_docs` (returns `GRAPH_DOCS` as plain text, split out of `get_catalog` for same size reason), `validate_graph`/`save_graph` (`isWorkflowGraph` + size caps + `validateGraphStrict` via shared async `checkGraph(userId, graph, byKey)` — computes the `githubLinked` flag lazily, only for graphs actually containing `event:github-*` nodes (`isGithubEventKey`), from `githubAppConfigured()` + `listInstallations(userId)`, so the designer's warning has MCP parity; **node `x`/`y` are optional over MCP** — `fillCoords` in `app/mcp/tools.ts` defaults absent coords to 0 (a *non-number* coord still fails the shape guard with its real message) and, when **any** node omitted one, the validated graph is re-laid-out by `layoutGraph` (`[id]/geometry.ts` — layered left→right, column = longest path over all edges, column width/row pitch from the real `nodeWidth`/`nodeHeight`, cycles break at depth 0); a graph carrying coords on every node is stored verbatim so a `get_workflow` → edit → `save_graph` round-trip never scrambles the user's canvas arrangement. `GRAPH_DOCS` + `GRAPH_SCHEMA` tell agents to omit them (external agents can't predict rendered node sizes, so hand-picked coordinates overlap); save rejects on hard errors, returns warnings; shape-guard rejection quotes first concrete violation via `graphShapeError` in `lib/workflow.ts` — diagnostic twin `isWorkflowGraph` delegates to — naming offending node/edge/field, e.g. non-string config values, so graph-authoring agents self-correct; designer's `saveWorkflow` keeps generic throw, canvas can't produce bad shapes), `run_workflow` (→ `executeWorkflowRun` with `trigger='manual'` — only writer of that trigger value; real side effects, same as scheduled run), `list_runs`, `get_run` (ownership via workflow join). **Registry domains (15)** — same file, same helpers (`obj`/`str`/`ok`/`fail`/`asId`), every mutation `invalidateUserRegistry(userId)`, variable mutations also `subscriptionsChanged()`: **memory (8)** `list_memory_stores` (registry rows + `countMemoryItems`), `create_memory_store` (tier cap `memoryStores` via `countKind` + `MAX_ENTRIES_PER_KIND` backstop)/`update_memory_store`/`delete_memory_store` (kind-scoped SQL, items cascade), `list_memory_items` (ownership check → `listMemoryItems`, 100), `search_memory`/`save_memory`/`forget_memory` (→ `executeMemoryTool(userId, storeId, "memory_*", json, "manual")` — embedding calls, so they spend credits); **registry read (1)** `list_registry` (mcpServers/skills/memoryStores/variables from `getUserRegistry` — its projection is the secret gate: `getMcpSecrets`/`getVariableValues` are never called here, MCP tokens surface only as `hasToken`, and `value` is emitted only for non-secret variables); **skills (3)** `create_skill`/`update_skill`/`delete_skill` (description = the instruction text, ≤`MAX_DESCRIPTION`); **variables (3)** `create_variable` (mode fixed at creation)/`update_variable` (stored `secret` read back, omitted `value` keeps the stored one, never returns a value)/`delete_variable`. The one-statement `registry_entry` INSERT/UPDATE/DELETEs are deliberately **duplicated** from the dashboard FormData actions (`memory`/`settings`/`workflows/[id]` `actions.ts`) rather than extracted — each carries a `ponytail:` comment naming its twin; deletes are kind-scoped so an id of the wrong kind can't be removed. Tool failures return as `isError` results, never JSON-RPC errors.
